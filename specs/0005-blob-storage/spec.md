# Spec 0005: Blob storage for extension bodies

- **Status**: draft
- **Date**: 2026-10-07
- **Author**: vgsml, Claude

## Summary

Extension bodies are stored once, as content-addressed precompressed streams, in an object store
behind one interface. A blob service on top:

- **spools** an incoming file;
- lets the caller **verify** it: footer, upstream signature, init symbol;
- **commits** it: precompresses (spec 0002), uploads, and records the result;
- **serves** a channel's file from the stored stream plus that channel's signature, as gzip with
  `HEAD` and `Range`. Every byte is verified against chunk digests held in the database before it
  is sent.

Tenants belong to **storage domains**: named stores from config. Dedup happens inside a domain,
which is how data residency and sovereign clouds are kept apart (spec 0001).

Delivery is phased, like spec 0004:

1. the interface, the contract suite, `fs`, `s3` with static key files (MinIO, Cloudflare R2,
   S3-compatible stores), the service, and migration 0002;
2. `azureblob`, with spec 0004's Azure credentials;
3. **deferred with the AWS/GCP work**: platform identity for `s3` on AWS (IRSA, Pod Identity,
   instance roles, through a hardened `internal/cloud/aws`), and `gcs`.

## Problem

Spec 0001 serves `body ‖ channel signature` without copying binaries per channel or per tenant.
Spec 0002 built the pieces:
- the composite body hash;
- a precompressed deflate stream ending with a sync flush;
- per-chunk stream digests;
- a gzip writer that verifies each chunk before sending it.

Nothing stores those streams yet. Every deployment keeps objects somewhere different, so the object
store is pluggable (the owner's rule: Azure is one option, everything cloud-specific behind an
interface).

## Design

### Objects and records

- **Object.** The precompressed stream of one body is stored under its own content address:
  `streams/<stream hash hex>`, where the stream hash is spec 0002's `StreamHash`. Objects are
  immutable in content. A write to an existing key writes the same bytes, so overwriting is always
  safe.
- **Record.** A database row holds what serving needs and the object store must not be trusted
  with:

```text
blobs            domain, body_hash, stream_hash, body_len, body_crc32, stream_len,
                 stream_chunks (32 bytes per MiB of stream), corrupt_at null, created_at
                 pk (domain, body_hash); index (domain, stream_hash)
storage_domains  name pk, kind, store_id, created_at
                 -- store_id: a hash of the store's identity (kind, endpoint or account, bucket or
                 -- container or root, prefix), pinned at first use
```

- **No raw body is stored.** Signing needs only the body hash, serving uses the stream, and the rare
  plain-name answer inflates it. This amends spec 0001, which planned to keep a raw copy too.
- **The footer belongs to the Build** (spec 0008), not to the blob.

**Migration 0002** (`-- +min_reader 1`, purely additive):

| Column | PostgreSQL | SQL Server | SQLite |
| --- | --- | --- | --- |
| hashes | `varchar(64)` hex | `nvarchar(64) BIN2` | `TEXT` |
| `body_crc32`, lengths | `bigint` | `bigint` | `INTEGER` |
| `stream_chunks` (up to about 33 KB at 1 GiB) | `bytea` | `varbinary(max)` | `BLOB` |

It also adds `tenants.storage_domain` as `varchar(16)` / `nvarchar(16) BIN2` / `TEXT`,
`NOT NULL DEFAULT 'default'`. On SQL Server the default constraint is named.

### The store interface

```go
type Store interface {
    // Put stores a complete object; it becomes visible only when complete, and replaces any
    // existing object with the key.
    Put(ctx context.Context, key string, r io.ReaderAt, size int64) error
    // Get reads n bytes from off (n < 0: to the end).
    Get(ctx context.Context, key string, off, n int64) (io.ReadCloser, error)
    Stat(ctx context.Context, key string) (size int64, err error)          // ErrNotFound
    Delete(ctx context.Context, key string) error                          // GC (spec 0008)
    List(ctx context.Context, prefix string, fn func(key string, size int64, modified time.Time) error) error
}
```

- **Keys** are generated by kista: `streams/<64 lowercase hex>`, `tmp/<uuid>`, and
  `kista-domain.json` (the marker). They are validated against exactly this grammar on every call,
  with no upper case, no `..`, no other prefixes. `List` accepts only `streams/` and `tmp/`.
  Configured prefixes are validated the same way.
- **Bounded calls.** Every call has a timeout on time to first byte and on idle time. There are at
  most 3 attempts, counting the SDK's own retries. Clients ignore proxy environment variables and do
  not follow redirects.
- **Errors** keep the backend's status, an error code of the expected shape, and a request id, never
  bodies, keys, URLs or principals. The SDKs' own error strings, which include the URL and body, are
  never wrapped.

### Backends

**`fs`: a local directory** (phase 1). It also covers a Kubernetes persistent volume.
- All access goes through `os.Root`, so no path and no symlink can leave the root.
- `Put` writes `tmp/<uuid>` (`O_EXCL`, mode `0600`) and fsyncs it, renames it into place, then
  fsyncs the directory. The rename replaces the old object atomically. Directories are created with
  mode `0700`.
- A shared `ReadWriteMany` volume makes every pod a writer of every object. That is documented.

**`s3`: S3-compatible stores** (phase 1; `github.com/minio/minio-go/v7`, Apache-2.0).
- **Config:**
  - `endpoint`: an https host; http only on loopback with `profile: dev`;
  - `bucket` and `prefix`;
  - `region`, required (no `GetBucketLocation` lookup; R2 uses `auto`; jurisdiction endpoints such
    as `<acct>.eu.r2.cloudflarestorage.com` for residency);
  - `lookup: path|dns`;
  - `sse: none|s3|kms`, required: R2 and MinIO without KMS take `none`, AWS takes `s3` or `kms`,
    with `kms_key_id` for `kms`.
- **Credentials in phase 1:** static access-key and secret files (`access_key_file`,
  `secret_key_file`, mode `0600`), wrapped in kista's own `credentials.Provider`. minio-go's IAM,
  chain, environment and file providers are never used: they read `AWS_*`, `MINIO_*`,
  `~/.aws/credentials` and container-credential URLs from the environment. Platform identity for AWS
  is deferred to phase 3.
- **Put:** a single PUT, or a multipart upload from the spool file (`ReadAt`, no buffering), aborted
  on every error. Documentation adds an `AbortIncompleteMultipartUpload` lifecycle rule.
  `MaxRetry` is capped.
- Least privilege: `s3:PutObject`, `s3:GetObject`, `s3:DeleteObject` and `s3:ListBucket` on the
  prefix, plus `kms:GenerateDataKey` and `kms:Decrypt` for SSE-KMS.

**`azureblob`: Azure Blob Storage** (phase 2; `azblob`, with `internal/cloud/azure` credentials).
- Config: `account`, `container`, `cloud` (the blob host is derived from it), `prefix` and
  `identity`.
- `Put` stages blocks whose ids are derived from the stream hash and the block index, then commits
  the block list. Two replicas writing one key stage identical blocks, so neither commit invalidates
  the other.
- SAS tokens and connection strings are refused. A shared key (`account_key_file`) and an `endpoint`
  override are allowed only with `profile: dev` on loopback, for the Azurite emulator.
- Least privilege: Storage Blob Data Contributor on the container. The documentation says to set
  `allowBlobPublicAccess = false`.

**`gcs`: Google Cloud Storage** is deferred to phase 3, with the GCP work. It will use REST with
Application Default Credentials.

### Storage domains

```yaml
blob:                               # file-only, like signers
  domains:
    - name: default
      kind: s3
      s3: { endpoint: minio.internal:9000, bucket: kista, region: us-east-1, sse: none,
            access_key_file: /run/secrets/s3-access, secret_key_file: /run/secrets/s3-secret }
    - name: cn
      kind: azureblob                 # phase 2
      azureblob: { account: kistacn, container: bodies, cloud: china,
                   identity: { kind: workload, client_id: "…", tenant_id: "…" } }
  spool_dir: /var/lib/kista/spool   # required outside dev
  max_body: 1GiB
  max_ingests: 4                    # concurrent spools; disk use is about max_ingests × 2 × max_body
```

- **Default.** Without a `blob` block, kista uses one `fs` domain, `default`, under
  `/var/lib/kista/blobs` (in dev, a directory beside the SQLite file). kista needs nothing but
  DuckDB.
- **Pinned.** At startup every configured domain's `store_id` is compared with
  `storage_domains`. A domain that now points at another store refuses to start. Two domains whose
  stores overlap (same kind and bucket, container or root, with one prefix containing the other) are
  refused at config validation.
- **Marker.** Each domain's store holds `kista-domain.json`: the domain name, the store id, and the
  deployment's id (kept in the database). A store whose marker names another deployment or domain is
  refused. Two kista deployments never share a prefix, so one's garbage collection cannot delete the
  other's objects.
- **Not public.** At startup kista makes an anonymous, unsigned `HEAD` of the marker. If that
  succeeds, the domain is public, and kista refuses to start. The same check runs periodically.
- **Tenants.**
  - A tenant's domain is set at creation (`kista admin tenant create … -domain cn`), validated
    against the loaded config, and never changes in this spec.
  - At startup, every tenant's domain must exist in config. A tenant whose domain is missing is
    served nothing; its requests fail closed, and the condition is logged. It never falls back to
    another domain.

### Spool, verify, commit

```go
sp, err := svc.Spool(ctx, domain, r)   // the whole file, at most max_body + 256 bytes
// sp.File() *extfile.File: metadata, body hash, signature (spec 0002 extfile.Open over the spool)
// the caller verifies: the footer against the declared name/version/platform, the upstream
// signature (spec 0009), the init symbol (spec 0008)
rec, err := sp.Commit(ctx)             // stores the body
sp.Close()                             // always; removes the spool files; idempotent after Commit
```

- **Spool.**
  - `spool_dir` is a directory kista creates with mode `0700` and checks it owns.
  - Files are created with `O_EXCL` under random names, mode `0600`.
  - At most `max_ingests` spools exist at once; a semaphore limits them, and the size cap applies
    while reading.
  - Leftover spool files are swept at startup.
  - The spool is read through one open descriptor, never reopened by path, so what the caller
    verified is what is stored.
- **Commit:**
  1. precompress the spooled body (spec 0002 `Precompress`), asserting the result's body hash equals
     the spool's;
  2. upload the stream to `streams/<stream hash>`, **always**, replacing any existing object;
  3. insert the record. If it exists (a dedup hit), keep the first record when its stream is still
     the uploaded one, otherwise update it to the new stream, and clear `corrupt_at`.
- **Why always upload:**
  - the same work and timing whether or not another tenant in the domain already stored the body, so
    an upload reveals nothing (spec 0001);
  - an object that is missing, planted or bit-rotted is repaired by the next commit of that body.

  The cost is a repeated upload per ingest of an already-stored body. An optimization for public
  upstream bodies is a follow-up.

### Serving

`svc.OpenGzip(ctx, rec, sig)` and `svc.OpenPlain(ctx, rec, sig)` take a **record that the caller
has already resolved through a Build it is authorized to see** (specs 0006 and 0008). There is no
lookup by a raw hash from a request.

Each returns a `File`:
- `Size`;
- `ETag`: `H("gz" ‖ body hash ‖ signature)` or `H("plain" ‖ body hash ‖ signature)`. The body hash
  is stable even if a stream is ever re-made; this amends spec 0001;
- `ContentType`: `application/gzip` or `application/octet-stream`, set so that `ServeContent` never
  sniffs and a `HEAD` reads nothing;
- `NewReader(ctx) io.ReadSeeker`, per request.

**Gzip.** The file is the gzip header, the stored stream, a final stored block with the 256
signature bytes, and the trailer. Total size: `stream_len + 279`; chunk boundaries sit at
`10 + k × 1 MiB`.
- A read fetches one ranged `Get` from the first chunk it needs up to the end of the requested range.
- It verifies each chunk against the record as it streams, and copies out only verified bytes. The
  last, partial chunk is checked at its exact length.
- A non-sequential read reopens the range.
- The header, the tail and the trailer are built in memory.

**Plain.** The plain name is fetched only through httpfs (spec 0002). It is served by inflating the
verified stream and appending the signature.
- No `Accept-Ranges` is sent, so httpfs downloads it whole; this is to confirm on the pin.
- The inflated length must equal `body_len`.

**Failure mid-response.** If a chunk fails verification after headers were sent, the reader returns
`ErrCorrupt`. The HTTP handler (spec 0006) must abort the connection
(`panic(http.ErrAbortHandler)`), so a client never sees a clean, truncated file. The record gets
`corrupt_at`, a metric and an alert are raised, and the next commit of the body repairs the object.
The store is not trusted, so a bucket writer can deny service but cannot serve a different body.

**Caching.** Records never change except for `corrupt_at`, so serving caches them by
`(domain, body hash)`. Per-request read buffers are never shared.

Spec 0006 limits multi-range requests: each range can pull whole chunks.

## Security

- **Integrity.** Objects are content-addressed. Every served byte is verified against chunk digests
  in the database first. A failure aborts the connection and is repaired on the next commit. The
  database is the trust root.
- **Isolation.**
  - Storage domains are pinned to their stores and marked with the deployment.
  - Overlapping stores are refused.
  - Dedup stays inside a domain and is unobservable, because every commit uploads.
  - Serving takes resolved records, never raw hashes.
- **Credentials:**
  - kista's own providers only, from files;
  - SDK credential chains and steering variables are not used;
  - shared keys and endpoint overrides only in dev on loopback;
  - TLS required off loopback.
- **Exposure:**
  - kista never sets ACLs;
  - it refuses to start when a domain's marker is anonymously readable;
  - the documentation sets S3 Block Public Access and `allowBlobPublicAccess = false`.
- **Resources:**
  - `max_body` and `max_ingests` bound spool disk use;
  - spool files are private, created with `O_EXCL`, removed on every path, and swept at start;
  - reads are bounded by ranges and timeouts.

## Testing

- **Contract suite** (`internal/blob/blobtest`), run by every backend:
  - Put/Get/Stat/Delete/List, with `List` reporting the modification time;
  - ranges at chunk boundaries;
  - a Put that replaces an existing key;
  - refused keys and prefixes;
  - a missing object is `ErrNotFound`;
  - an interrupted Put leaves no visible object;
  - concurrent Puts of one key;
  - errors without planted secrets;
  - steering environment variables (`AWS_*`, `MINIO_*`, `~/.aws` via `HOME`) are ignored.
- **Real servers in CI (Linux):**
  - MinIO, pinned by digest (SeaweedFS is the fallback if MinIO images go away), for `s3` with
    `sse: none`;
  - Azurite (`azurite-blob --skipApiVersionCheck --loose`, the well-known dev account) for
    `azureblob` in phase 2;
  - run as `docker run` steps, gated by `KISTA_TEST_S3` / `KISTA_TEST_AZUREBLOB` and required with
    `KISTA_TEST_REQUIRE_BLOB=1`;
  - `fs` always; macOS runs `fs` only.
- **Service:**
  - spool, verify, commit;
  - a caller that rejects the file stores nothing and leaves no spool;
  - `max_body`, `max_ingests`, the startup sweep;
  - a dedup hit still uploads, and repairs a planted object;
  - two commits racing;
  - the record round trip on all three databases;
  - `OpenGzip` bytes equal spec 0002's `WriteGzip`;
  - a range inside a chunk, a range across chunks, the last bytes;
  - a tampered object byte returns `ErrCorrupt` with nothing of that chunk, and sets `corrupt_at`;
  - plain bytes equal body plus signature, and the length is checked;
  - domain pinning: a changed `store_id`, overlapping stores, a foreign marker, a public marker, a
    tenant with a missing domain.
- **e2e.** A real extension is spooled, verified (footer, test signature) and committed into `fs`,
  then into MinIO. Served by `http.ServeContent` with a channel signature, DuckDB installs and loads
  it:
  - over `http://` (one `GET`);
  - over `https://` through httpfs (`HEAD`, then a ranged `GET`, with `ca_cert_file`);
  - and with the `.gz` missing, the plain name through httpfs.

  The e2e and CI path filters include `internal/blob/**`.

## Alternatives considered

- **Also store the raw body.** It doubles storage for a path DuckDB almost never takes.
- **Address objects by body hash.** Two compressors would race on one key with different bytes.
- **Skip the upload on a dedup hit.** It leaks whether another tenant stored the body, and it never
  repairs a bad object.
- **gocloud.dev/blob, or minio-go's own credential chain.** Both pull credentials and endpoints from
  the environment, around spec 0004's hardening.
- **The AWS SDK for S3.** minio-go is lighter, Apache-2.0, and speaks to R2 and MinIO directly. AWS
  identity (phase 3) plugs in as a credentials provider.
- **Verify a whole object before serving.** It costs a full read per request. Chunk verification
  stops at the first changed byte at no extra cost.
